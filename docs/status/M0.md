# M0: Setup, landscape and syntax survey
Machine: Ryzen 7 5700X desktop (Windows 11, Docker Desktop engine 29.8.2)   Date: 2026-11-22

## Built

- **Oracle.** Official `wazuh/wazuh-docker` single-node deployment, tag
  `v4.14.10` (commit `76ddb88b9c8b618a254a287f2684f93d3c5ac2f4`), the newest
  stable 4.x release. Image tags and digests, file hashes and the exact
  commands are in `oracle/README.md`. The compose file itself is not copied
  (GPLv2 header); it lives in the git-ignored checkout
  `oracle/wazuh-docker/`. One change: `oracle/compose.localhost.yml` binds
  every published port to 127.0.0.1, because the stack runs with the
  documented default passwords.
- **Logtest driver.** `oracle/logtest.py` (runs inside the manager container,
  calls `PUT /logtest` and `DELETE /logtest/sessions/{token}`) and the host
  wrapper `oracle/logtest.sh`: one log line per stdin line in, one JSON result
  per line out, all lines in one session.
- **UniFi content (added by Evan's request).** `oracle/install-unifi.sh`
  clones `evangress/wazuh-unifi-decoder` and `evangress/wazuh-unifi-rules`
  into the git-ignored `oracle/unifi/`, pins them, copies
  `ubiquiti_decoders.xml` to `/var/ossec/etc/decoders/` and
  `ubiquiti_rules.xml` to `/var/ossec/etc/rules/` (owner `wazuh:wazuh`,
  mode 660, as both READMEs say) and restarts the manager. Pinned commits:
  - `wazuh-unifi-decoder` `3a9a2d522840ed876e3f634232ea36392d94478f`
  - `wazuh-unifi-rules` `36193597001b99c94994972412253c3c712fcb93`
  No analysisd ERROR, CRITICAL or WARNING lines in `ossec.log` after the
  restart.
- **Survey.** `oracle/survey_syntax.py` counts elements and attributes in
  the stock ruleset inside the container; counts in
  `docs/syntax-survey-wazuh-4.14.10.json`, table and M1 subset in
  `docs/syntax.md`. Only counts are recorded.
- `docs/landscape.md`: existing engines, go.
- `LICENSE` (Apache-2.0) and the decided name and licence recorded in
  `CLAUDE.md` and `docs/SPEC.md`.

## Corrections to the spec (made on this branch)

- SPEC §4: decoder `prematch` and `regex` accept `osregex` and `pcre2`
  only; `osmatch` is valid for decoder `program_name` only. The spec said
  decoders use all three. (Source: the Wazuh 4.14 decoder syntax page and
  the 4.14.10 loader; confirmed by the stock counts, which show no
  `osmatch` on decoders.)
- SPEC §6: the logtest interface is confirmed: CLI
  `/var/ossec/bin/wazuh-logtest` and API `PUT /logtest`,
  `DELETE /logtest/sessions/{token}`. Both were run against the container.
- SPEC §4 additions recorded in `docs/syntax.md`: `action`, `status`,
  `url`, `category` are used more than several spec items and are added to
  M1; `srcip`, `dstip`, `srcport`, `dstport` occur in no stock rule.
- The pcre2 engine must support look-ahead (Evan's UniFi decoder uses it in
  150 of 151 regexes).
- The oracle version is 4.14.10, the same 4.14 line the UniFi content was
  tested on (its README says 4.14.8).

## Observations (verified)

- Events with a syslog program name are only tried against decoders that
  declare `<program_name>`; the UniFi decoder's own comment says the same
  and its CEF lines get program name `CEF`. M1 tests this against the
  oracle.
- Dotted field names (for example `event.id`) come back from logtest as
  nested JSON objects.

## How to stop and restart the stack; where secrets live

See `oracle/README.md` ("Stop, start, restart" and "Credentials and
certificates"). Short form, from `oracle/wazuh-docker/single-node`:
`docker compose -f docker-compose.yml -f ../../compose.localhost.yml stop`
/ `start` / `restart`. Certificates and keys are in
`oracle/wazuh-docker/single-node/config/wazuh_indexer_ssl_certs/`
(git-ignored). Passwords are the documented defaults from the upstream
compose file. The stack is left running.
